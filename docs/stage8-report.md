## 1. CSP decision — NO change needed for Pages-static hosting

**Verdict: the current CSP already covers everything the app does
once artwork + metadata are served from the same Pages project, so no
CSP entry is added in Stage 8.** The Stage 7 open item ("add the

site's own host. Verified by reading the code, not by assumption.

## 3. Config changes — wrangler.toml + caching headers

Done by Worker 1 (production config); verified by the coordinator
(`npm run build` exit 0, `npm run lint` 0 errors / 1 pre-existing
warning, re-run 19 Nov 2026; `dist/_headers` identical to
`public/_headers`).

- `repo/frontend/wrangler.toml` (new, 3,202 bytes): `name =
  "aurumagents"`, `pages_build_output_dir = "./dist"`. It is
  explicit that these are the only real wrangler fields for a
  direct-upload project — there is no build-command or
  production-branch field in the wrangler schema for direct uploads,
  so build command (`npm run build`, in `repo/frontend/`) and
  production branch (`main`) are recorded there as comments, along
  with the four production env vars (all public by design, baked in
  at build time from `.env`: `VITE_WC_PROJECT_ID` from `.env`,
  `VITE_CONTRACT_ADDRESS` empty until Stage 9, `VITE_BSC_RPC_URL` =
  `https://bsc-rpc.publicnode.com`, `VITE_BSC_RPC_FALLBACK_URL` =
  `https://bsc-dataseed.bnbchain.org`). Deliberately absent:
  `compatibility_date` / `[vars]` (no Pages Functions exist).
- Caching headers (added to `frontend/public/_headers`, security
  headers byte-identical):
  - `/artwork/*` → `Cache-Control: public, max-age=31536000, immutable`
  - `/metadata/*` → `Cache-Control: public, max-age=31536000, immutable`
  - `/index.html` → `Cache-Control: no-cache`
  Syntax verified against Cloudflare's `_headers` docs (single-splat
  path patterns; a request matching multiple rules inherits all of
  them, so artwork/metadata responses still get every security
  header from the `/*` block). Live observation (see §4): Pages
  serves `/index.html` as `Cache-Control: public, max-age=0,
  must-revalidate` — Cloudflare's normalisation of `no-cache`,
  semantically identical (must revalidate every time).
- `frontend/public/_headers` itself: security headers unchanged
  (see §1.2). No CSP change in Stage 8.
